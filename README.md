# 芙伊app 下载中心 —— 项目总说明

本仓库是 **芙伊app 下载中心**（GitHub Pages 静态站，地址 `https://1rc2.github.io/`）。
它不直接存放 APP，而是通过 GitHub Releases API **自动拉取**各应用仓库的最新安装包，
让用户在一个页面上下载多个应用，且每个应用更新时**无需改网页代码**。

---

## 一、项目体系结构

```
┌─────────────────────────────────────────────┐
│  本仓库：1rc2.github.io（下载中心网页）        │
│  index.html 中 CONFIG.apps 配置了应用列表      │
└──────────────┬──────────────────────────────┘
               │ 自动读取 GitHub Releases API
               ▼
┌─────────────────────────────────────────────┐
│  各应用仓库（公开仓库，每个仓库 = 一个应用）      │
│  例：sjkglxt → 数据库管理系统                   │
│  每个仓库发布 Release 时上传 APK 安装包          │
└─────────────────────────────────────────────┘
```

- **下载中心仓库**：`1rc2/1rc2.github.io` —— 存放网页 `index.html`，页面顶部有应用切换条；
- **应用仓库**：每个应用一个公开 GitHub 仓库，通过 **Release 资产** 提供 APK 下载；
- **连接方式**：网页按 `CONFIG.apps` 里的仓库名，逐个调用
  `https://api.github.com/repos/{用户名}/{仓库名}/releases` 拉取最新版本信息。

## 二、网页如何获取 APP 下载

1. 网页加载时，按 `CONFIG.apps` 数组顺序读取每个应用仓库的 Releases；
2. 取最新（非草稿、非预发布）的 Release，展示版本号、发布时间、更新说明；
3. 在 Release 资产中找到后缀为 `.apk`（或 `.aab`）的文件，渲染「下载」按钮；
4. 点击下载按钮 → 直接跳转到 GitHub 官方下载地址；
5. 每个仓库展示最近 N 个版本（`releaseCount`，默认 3），旧版本显示在「历史版本」区。

> 网页数据在浏览器 localStorage 缓存 10 分钟，之后自动重新拉取。

## 三、各应用仓库的更新需求（必要条件）

每个应用仓库必须满足以下条件，下载页才能正常显示：

| 条件 | 说明 |
|------|------|
| 公开仓库 | 私有仓库网页无法跨域读取，必须是 public |
| 发布 Release | 必须创建 Release（Tag 如 `v1.0.0`），且不能是「预发布/草稿」 |
| 上传安装包资产 | Release 资产文件名后缀必须是 `.apk`（安卓）或 `.aab` |
| 更新说明 | Release 的说明框里写清本次更新内容（可选但推荐） |

## 四、发布新版本（应用更新流程）

各应用仓库的维护者按以下步骤更新：

1. 修改应用代码 → 打包出新的 `.apk` 安装包；
2. 打开对应仓库的 **Releases** 页 → **Draft a new release**；
3. 创建 Tag（版本号 `v主.次.修订`，如 `v1.0.1`，不要与旧版本重复）；
4. 填写版本标题与更新说明；
5. 上传新版 `.apk` → 点 **Publish release**；
6. 约 1~10 分钟后，下载中心网页自动显示新版本，无需改网页。

## 五、新增一个应用（加入下载中心）

1. 确认该应用仓库已公开，且已发布带 `.apk` 资产的 Release；
2. 编辑本仓库 `index.html` 中的 `CONFIG.apps`，复制一项配置并修改：

```js
apps: [
  {
    repo: "sjkglxt",        // 应用所在仓库名（不含用户名）
    appName: "数据库管理系统", // 切换条上显示的应用名
    color: "#2563eb"        // 该应用的主题强调色
  }
  // 新增应用：复制上面一项，改 repo / appName / color 即可
]
```

3. 提交并推送 `index.html`，顶部切换条自动出现新应用标签。

## 六、移除一个应用

从 `CONFIG.apps` 数组中删掉对应项并推送即可；被移除的应用不再显示，
其仓库与历史 Release 不受影响。

## 七、相关文件

| 文件 | 作用 |
|------|------|
| `index.html` | 下载中心页面（含应用配置、拉取逻辑、渲染逻辑） |
| `robots.txt` | 搜索引擎抓取规则 |
| `sitemap.xml` | 站点地图，帮助搜索引擎收录 |
